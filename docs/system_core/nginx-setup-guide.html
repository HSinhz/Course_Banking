Thêm Nginx vào Banking Basic

Nginx làm load balancer: nhận request từ client, phân phối đều sang nhiều instance API, health check và tự loại server chết.

Client chỉ biết Nginx (port 80). Hai API instance chạy trong Docker private network — không expose ra ngoài trực tiếp.

Nginx làm gì trong hệ thống này
⚖️

Load balancing

Phân phối request đều giữa API 1 và API 2 theo thuật toán round-robin (mặc định). Request 1 → API 1, Request 2 → API 2, Request 3 → API 1…

❤️

Health check

Nginx chủ động gọi GET /health mỗi 10s. Nếu API 1 trả về lỗi 2 lần liên tiếp → loại khỏi pool. Khi hồi phục → tự đưa vào lại.

🔒

Ẩn API server

Port 5199 của API không expose ra ngoài Docker network. Chỉ Nginx ở port 80 nhận request từ bên ngoài — giảm attack surface.

🔄

Failover tự động

API 1 crash? Nginx phát hiện qua health check và route 100% sang API 2. Không cần can thiệp thủ công.

Request flow chi tiết
1
Client gửi request → POST http://localhost/api/v1/transfers (port 80, Nginx)
2
Nginx nhận → chọn upstream server theo round-robin, thêm header X-Real-IP và X-Forwarded-For
3
Forward tới API instance → HTTP proxy tới api:5199 qua internal Docker network
4
API xử lý → đọc JWT, gọi DB/Redis, trả JSON response
5
Nginx forward response về client → client không biết request đi qua instance nào
File cần tạo: docker/nginx/nginx.conf — đặt trong thư mục docker/ cùng chỗ với init.sql hiện tại.
docker/nginx/nginx.conf 
# Worker processes: auto = số CPU cores
worker_processes  auto;

events {
    # Số kết nối đồng thời tối đa mỗi worker
    worker_connections  1024;
}

http {
    include       /etc/nginx/mime.types;
    default_type  application/octet-stream;

    # Log format có request time để đo latency
    log_format main '$remote_addr - $upstream_addr [$time_local] '
                     '"$request" $status $body_bytes_sent '
                     'rt=$request_time ut=$upstream_response_time';

    access_log  /var/log/nginx/access.log  main;
    error_log   /var/log/nginx/error.log   warn;

    sendfile        on;
    keepalive_timeout  65;

    # ── Upstream: pool các API instance ──────────────────────────
    upstream banking_api {
        # least_conn: chuyển request tới server ít connection nhất
        # (phù hợp hơn round-robin khi request có độ trễ không đều)
        least_conn;

        # Tên service trong Docker Compose: api1, api2
        server  api1:5199  max_fails=2  fail_timeout=10s;
        server  api2:5199  max_fails=2  fail_timeout=10s;
        # max_fails=2: sau 2 lần lỗi trong fail_timeout → đánh dấu down
        # fail_timeout=10s: thời gian giữ trạng thái "down" rồi thử lại

        # Giữ kết nối tái sử dụng tới upstream (giảm overhead TCP)
        keepalive  16;
    }

    # ── Virtual server ───────────────────────────────────────────
    server {
        listen       80;
        server_name  _;  # chấp nhận mọi hostname

        # Timeout cho upstream (API xử lý chậm)
        proxy_connect_timeout  5s;
        proxy_send_timeout     60s;
        proxy_read_timeout     60s;

        # ── Health check endpoint riêng (không qua upstream) ──
        location /nginx-health {
            access_log  off;
            return  200  "nginx ok\n";
            add_header  Content-Type  text/plain;
        }

        # ── Forward tất cả request vào API upstream ────────────
        location / {
            proxy_pass          http://banking_api;
            proxy_http_version  1.1;

            # Cần cho keepalive upstream
            proxy_set_header  Connection  "";

            # Truyền IP thật của client vào API
            proxy_set_header  X-Real-IP         $remote_addr;
            proxy_set_header  X-Forwarded-For   $proxy_add_x_forwarded_for;
            proxy_set_header  X-Forwarded-Proto  $scheme;
            proxy_set_header  Host               $host;
        }
    }
}
🔀

least_conn

Chọn server ít connection đang active nhất. Tốt hơn round-robin khi transfer interbank (chậm) và query balance (nhanh) cùng chạy — tránh dồn hết vào 1 server.

🚨

max_fails + fail_timeout

Sau max_fails=2 lần lỗi trong fail_timeout=10s, server đó bị đánh dấu "unavailable" trong 10s. Sau đó Nginx thử lại 1 request — nếu OK thì đưa vào pool.

📡

X-Forwarded-For

API cần header này để biết IP thật của client (không phải IP của Nginx). Dùng trong logging, rate limiting, hoặc audit log.

⚡

keepalive 16

Nginx giữ tối đa 16 kết nối TCP idle tới mỗi upstream. Request tiếp theo tái sử dụng ngay — không tốn RTT cho TCP handshake mới.

Thay đổi docker-compose.yml: Thêm service nginx, api1, api2. API không expose port ra ngoài nữa — chỉ Nginx nhận traffic.
docker-compose.yml (phần thêm mới) 
services:

  # ── Nginx load balancer ──────────────────────────────────────
  nginx:
    image: nginx:1.26-alpine
    ports:
      - "80:80"          # port duy nhất expose ra ngoài
    volumes:
      - ./docker/nginx/nginx.conf:/etc/nginx/nginx.conf:ro
    depends_on:
      api1:
        condition: service_started
      api2:
        condition: service_started
    restart: unless-stopped

  # ── API instance 1 ───────────────────────────────────────────
  api1:
    build:
      context: .
      dockerfile: src/Banking.API/Dockerfile
    environment:
      - ConnectionStrings__Default=Host=postgres;Port=5432;Database=banking_basic;Username=postgres;Password=admin
      - Jwt__Key=dev-only-super-secret-key-change-me-32bytes-min!!
      - Jwt__Issuer=BankingBasic
      - Jwt__Audience=BankingBasicClient
      - Redis__Connection=redis:6379
    depends_on:
      postgres:
        condition: service_healthy
      redis:
        condition: service_started
    # KHÔNG có "ports:" — chỉ accessible qua internal Docker network
    restart: unless-stopped

  # ── API instance 2 (cấu hình giống api1) ─────────────────────
  api2:
    build:
      context: .
      dockerfile: src/Banking.API/Dockerfile
    environment:
      - ConnectionStrings__Default=Host=postgres;Port=5432;Database=banking_basic;Username=postgres;Password=admin
      - Jwt__Key=dev-only-super-secret-key-change-me-32bytes-min!!
      - Jwt__Issuer=BankingBasic
      - Jwt__Audience=BankingBasicClient
      - Redis__Connection=redis:6379
    depends_on:
      postgres:
        condition: service_healthy
      redis:
        condition: service_started
    restart: unless-stopped

  # postgres, pgadmin, redis, redisinsight — giữ nguyên như cũ
  postgres: ...
  redis: ...
Cần có Dockerfile: Hiện project chưa có src/Banking.API/Dockerfile. Xem tab "Thay đổi trong API" để xem Dockerfile mẫu.
1 — Thêm Dockerfile cho Banking.API
src/Banking.API/Dockerfile 
# Build stage
FROM mcr.microsoft.com/dotnet/sdk:10.0 AS build
WORKDIR /src

# Copy csproj và restore trước (layer cache)
COPY src/Banking.Domain/Banking.Domain.csproj           src/Banking.Domain/
COPY src/Banking.Application/Banking.Application.csproj src/Banking.Application/
COPY src/Banking.Infrastructure/Banking.Infrastructure.csproj src/Banking.Infrastructure/
COPY src/Banking.API/Banking.API.csproj                 src/Banking.API/
RUN dotnet restore src/Banking.API/Banking.API.csproj

# Copy toàn bộ source và publish
COPY src/ src/
RUN dotnet publish src/Banking.API/Banking.API.csproj \
    -c Release -o /app/publish --no-restore

# Runtime stage (image nhỏ hơn, không có SDK)
FROM mcr.microsoft.com/dotnet/aspnet:10.0 AS runtime
WORKDIR /app
COPY --from=build /app/publish .

# Lắng nghe trên port 5199 bên trong container
ENV ASPNETCORE_URLS=http://+:5199
EXPOSE 5199

ENTRYPOINT ["dotnet", "Banking.API.dll"]
2 — Thêm health check endpoint vào Program.cs

Nginx cần endpoint này để kiểm tra API còn sống không. Thêm trước app.Run():

src/Banking.API/Program.cs — thêm 1 dòng 
// Thêm dòng này trước app.Run()
app.MapGet("/health", () => Results.Ok(new { status = "healthy" }));

app.Run();
3 — Thêm ForwardedHeaders middleware

Để API đọc được IP thật của client từ header X-Forwarded-For mà Nginx gắn vào:

src/Banking.API/Program.cs — thêm vào đầu pipeline 
// Thêm TRƯỚC app.UseCors() và app.UseAuthentication()
app.UseForwardedHeaders(new ForwardedHeadersOptions
{
    ForwardedHeaders = ForwardedHeaders.XForwardedFor | ForwardedHeaders.XForwardedProto
});

app.UseCors("frontend");
app.UseAuthentication();
// ...
Tại sao cần: Không có middleware này, HttpContext.Connection.RemoteIpAddress sẽ trả IP của Nginx (172.x.x.x) thay vì IP thật của client. Ảnh hưởng tới audit log và rate limiting.
4 — Bỏ UseUrls hardcode (không cần nữa)

docker compose up --build -d

# Xem Nginx đang forward tới instance nào (log)
docker compose logs nginx -f
Kiểm tra failover
1
Kill api1 → docker compose stop api1
2
Gửi request → curl http://localhost/health — vẫn OK vì Nginx tự route sang api2
3
Xem Nginx log → thấy upstream server temporarily disabled cho api1
4
Start lại api1 → docker compose start api1 — Nginx tự đưa vào pool sau 10s
Kiểm tra load balancing
Terminal — xem request phân phối đều 
# Gửi 10 request liên tiếp và xem upstream trong log
for i in {1..10}; do curl -s http://localhost/health > /dev/null; done

# Log Nginx sẽ hiển thị upstream_addr xen kẽ: api1:5199 và api2:5199
docker compose logs nginx | grep upstream_addr
